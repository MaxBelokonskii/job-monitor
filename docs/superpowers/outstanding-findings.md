# Незакрытые замечания ревью

Перечень существовал только в переписке: спецификация подпроекта 2 ссылалась
на «остальные тринадцать замечаний ревью и аудита подпроекта 1», не называя
их. Диалог однажды закончится, и вместе с ним исчезнет список — поэтому он
записан здесь.

**Состояние проверено по коду 2026-09-11**, а не переписано по памяти: три
замечания за это время закрылись, одно из них — попутно, и продолжать
числить их долгом было бы неправдой.

## Закрыто

| № | Что было | Чем закрыто |
|---|----------|-------------|
| M-1 | `PATCH /api/presets/{id}` с нечисловой `position` давал 500 | попутно, при переписывании роута под M-2 (задача 7 подпроекта 2): теперь 400 с объяснением |
| M-2 | тот же `PATCH` применялся наполовину: 422 возвращался уже после переименования | подпроект 2, задача 7 — сначала проверяется всё, потом пишется всё |
| M-3 | файл резюме писался до строки в базе, а стирался до неё же | подпроект 2, задача 7 — файл и строка появляются и исчезают вместе |

## Открыто

Все проверены исполнением; напротив каждого — как воспроизвести.

| № | Замечание | Проверка |
|---|-----------|----------|
| M-4 | `upload_resume` читает тело целиком в память (`await request.body()`), проверка `content-length` — оптимизация, а не защита | `api/resumes_routes.py`, отсутствие потокового чтения |
| M-5 | `activate_preset` не ловит `WorkerNotRunning` из `manager.stop()`: воркер, успевший умереть сам между `running()` и `stop()`, даёт 500 вместо 409 | `api/presets_routes.py`, блок `for name in manager.running()` |
| M-6 | на 409 теряется список уже остановленных воркеров: клиент не знает, что часть встала | там же — `stopped` собирается, но `raise` уходит без него |
| M-7 | сводка пресета отдаёт `resume_id`, а не имя файла: интерфейсу приходится знать библиотеку, чтобы показать «какое резюме» | `GET /api/presets` → ключи `[…, resume_id]` |
| M-8 | `file_path` из старых настроек не переносится в библиотеку резюме, а отбрасывается | `job_monitor/presets.py::LEGACY_DROPPED_FIELDS` |
| M-9 | заменить файл резюме нечем: только удалить и загрузить заново, а удалить используемое пресетом запрещено | в `api/resumes_routes.py` нет ни `PUT`, ни `replace` |
| M-10 | `PLACEHOLDERS` в `workers/telegram.py` не читает никто: подписи в интерфейсе написаны руками и разойдутся с кодом при первой правке | `grep PLACEHOLDERS frontend/app.js` — пусто |
| M-11 | `GET /api/resumes` отдаёт `stored_name` — внутреннее имя файла на диске | ключи ответа: `[id, original_name, size_bytes, stored_name, uploaded_at]` |
| M-12 | `PATCH /api/presets/{id}` принимает `{"name": 123}` и сохраняет строку `"123"` | ответ 200, имя пресета становится `'123'` |
| M-13 | `test_every_handler_is_reachable` ослаблялся в подпроекте 1; нынешняя форма выглядит корректной, но проверка не пересматривалась | `tests/test_frontend_events.py` |

Плюс два замечания мутационного аудита того же периода: идемпотентность
переноса старых критериев и тест «в импорте нет секретов» держались за счёт
соседних проверок, а не собственных.

## Чего в этом списке нет

Отсутствие CI отсюда ушло: прогон настроен (`.github/workflows/tests.yml`).
Обязательность проверок для слияния намеренно не включена — решение
партнёра.

Политика хранения истории (`tg_found` и `worker_events` растут
неограниченно) и адаптивная вёрстка под узкие экраны — не замечания ревью, а
признанные границы области работ; они названы в спецификациях.
