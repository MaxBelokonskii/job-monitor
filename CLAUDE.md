# Job Monitor — как здесь работать

Этот файл читается в начале каждой сессии. В нём то, чего **нельзя вывести из
кода**: правила владельца, следы уже совершённых ошибок и повторяющиеся ловушки.
Описание структуры не дублируется — оно в `структура.txt` и `README.md`.

## Что это такое и почему цена ошибки высокая

FastAPI + Telethon + Selenium: ищет вакансии в Telegram-каналах и на hh.ru,
складывает в очередь, умеет откликаться сам. Приложение **действует от имени
живого человека в его настоящих аккаунтах** — пишет незнакомым людям в личку и
жмёт «Откликнуться» на hh.ru. Отозвать отправленное нельзя, а за перебор
Telegram и hh.ru ограничивают аккаунт.

Отсюда общее правило: **молчаливо неверное действие хуже видимого отказа.**
Когда выбор между «сделать не то» и «не сделать и сказать» — второе.

Проект унаследован у предыдущего автора. Его данные вычищены; если где-то
всплывут чужие ключевые слова, каналы или резюме — это дефект, а не пример.

## Твёрдые правила

Нарушать нельзя, даже если кажется, что стало бы лучше.

- **Регион поиска hh.ru — константа**, а не настройка (`HH_AREA_ID`, решение
  D8). Владелец попросил явно.
- **Резюме хранится в каталоге данных, а не в каталоге проекта** (D11). Именно
  так у предыдущего автора утекло резюме с ФИО, телефоном и почтой.
- **Сервер слушает только `127.0.0.1`.** Ни `0.0.0.0`, ни настройки для этого.
- **Секретов нет** в базе, ответах API, логах и репозитории. `TG_API_HASH`
  живёт только в `.env` каталога данных с правами `0600`.
- **Пути к состоянию — только через `job_monitor/paths.py`.** Единственное
  место, где они вычисляются.
- Никаких `eval` / `exec` / `pickle` / `marshal` / `shell=True` и установки
  пакетов в рантайме.
- **Никогда не запускать `git checkout` / `restore` / `stash` / `clean` /
  `reset`.** Незакоммиченная работа владельца этим уничтожается безвозвратно.
  Нужно сравнить с прошлой версией — `git show HEAD:путь > /tmp/копия` и `cp`.
- **Тесты-растяжки только усиливаются, не ослабляются.** `tests/test_frontend_safety.py`
  — растяжка плана укрепления, её не трогать вовсе.
- **Обязательные проверки статуса в CI включать не надо** — владелец попросил,
  чтобы прогон просто шёл.
- **Никогда не запускать воркеры с выключенным безопасным режимом** ради
  проверки. Это отправит реальные сообщения и отклики.

## Процесс

Так шли все предыдущие подпроекты, и это работало:

1. **Брейншторм** (`superpowers:brainstorming`) → спецификация в
   `docs/superpowers/specs/`, имя вида ГГГГ-ММ-ДД-тема-design.md.
2. **План** (`superpowers:writing-plans`) → `docs/superpowers/plans/`.
3. **Исполнение** по плану, задача за задачей, тест раньше кода.
4. Ветка → ПР → CI → слияние. В `master` напрямую не коммитить.

Решения нумеруются сквозно (`D1`, `D2`, …) и живут в разделах «Принятые
решения» спецификаций. Последний занятый номер спрашивай у репозитория, а не у
этого файла — он устареет:

```bash
grep -rho "D[0-9]\+" docs/superpowers/specs/ | sort -u -V | tail -1
```

**Каждый новый тест проверяй мутацией.** Сломай то, что он якобы проверяет, и
убедись, что он покраснел. Этот проект уже ловил с десяток тестов, зелёных при
сломанном коде. Рецепт:

```bash
cp файл.py /tmp/bak
# внести мутацию
.venv/bin/pytest tests/нужный_тест.py -q
cp /tmp/bak файл.py
```

**Фронтенд проверяй в браузере.** Три из четырёх дефектов прошлого подпроекта и
единственный дефект тура нашлись только открытием страницы, а не чтением кода.

## Команды

```bash
make install   # .venv + зависимости
make test      # без node часть тестов пропускается — прогон сам скажет сколько
make run       # http://127.0.0.1:8000
```

CI (`.github/workflows/tests.yml`) гоняет то же на 3.11 и 3.13 плюс
`pre-commit run --all-files` (свой `check-no-secrets` и `detect-secrets`).
Если хук просит `git add .secrets.baseline` — добавь и повтори коммит.

## Повторяющиеся ловушки

Каждая уже стоила отдельного разбора. Проверь их прежде, чем объявлять работу
готовой.

**Двойник добрее реальности.** Главный источник дефектов проекта. Фальшивый
Selenium-драйвер отвечал одной кнопкой на любой селектор — и авто-отклик
засчитывал несостоявшуюся отправку как успешную, а тест на это был зелёным. Другой двойник искал по
подстроке, игнорируя тег, — и не заметил, что hh.ru сменил `div` на `section`.
Двойник обязан быть **не добрее** настоящего: различать теги, точное и
частичное совпадение атрибутов, объединения XPath через `|`.

**Проверка, зелёная из-за соседней.** Тест «уже откликались — не кликаем» был
зелёным потому, что до клика дело не доходило по другой причине. Всегда пиши
обратную сторону: проверку, что условие не срабатывает всегда.

**Проверка, зелёная на пустом множестве.** Разбор исходника регулярным
выражением обязан утверждать, что нашёл хотя бы N штук. Иначе сломанный шаблон
даёт зелёный прогон «на ничём».

**Сравнение с точным текстом разметки.** `overview.count('<details class="field-group">')`
упало от добавленного `id`, не заметив, что аккордеонов меньше не стало.
Сравнивай по свойству, а не по литералу.

**`[hidden]` слабее любого класса с `display`.** У браузерного правила нулевая
специфичность. Узел с `display: flex` останется виден, сколько ему ни выставляй
`hidden`. В слое обучения это закрыто правилом `#tourLayer [hidden]`.

**Кэш статики.** Новый файл фронтенда обязан попасть в `VERSIONED_ASSETS`
(`api/main.py`). Забудешь — браузер отдаст старую версию, и правки «не
приезжают». `Cache-Control: no-cache` от этого не спасает: он управляет тем, как
сохранится НОВЫЙ ответ, а не записью, уже лежащей в кэше.

**Миграции SQLite.** `ADD COLUMN IF NOT EXISTS` не существует, а `executescript`
коммитит по ходу — оборвавшаяся миграция оставляет базу наполовину. Шаг может
быть строкой ИЛИ функцией; повторяемость обеспечивай сам, через
`PRAGMA table_info`. См. миграцию 004 как образец.

**`NOT NULL DEFAULT` действует только когда колонки нет в списке INSERT.**
Добавил колонку с дефолтом — проверь всех, кто вставляет строки явным списком.

**Словарь статусов — русские строки, уже лежащие в базах пользователей**
(`job_monitor/statuses.py`). Переименование значения ломает существующие
установки. Меняй только через миграцию.

**Инварианты фронтенда.** Ноль атрибутов `on*=` и ноль сборки разметки строками
— на этом держится `script-src 'self'` без `unsafe-inline`. Все кнопки через
`data-action`; `ACTIONS` в `app.js` — объектный литерал, и тесты разбирают его
текстом, поэтому дописывать в него из другого файла нельзя. `tour.js`
подключается ПЕРЕД `app.js` именно поэтому. Опрос состояния — один
(`/api/state`).

## Что известно как непроверенное

Говори об этом честно, не выдавай за работающее:

- **Авто-отклик на hh.ru против живой разметки.** Логика вычищена и покрыта
  тестами, но совпадают ли наши `data-qa` с сегодняшними на hh.ru — чтением
  кода не устанавливается. Проверяется одним откликом на настоящей вакансии.
  Владелец этой функцией пока не пользуется.
- **Авто-отправка в Telegram** покрыта тестами целиком, включая паузу на
  `FloodWaitError`; вживую владельцем не гонялась.
- **История не подрезается**: `tg_found` и `worker_events` растут без границ.
  Осознанный долг, записан в спецификации подпроекта 2.
- **Узкие экраны**: интерфейс рассчитан на ширину от 900 px и под телефон не
  адаптирован.
